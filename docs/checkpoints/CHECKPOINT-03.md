# Checkpoint 03 — конфигурация ключа и первый ответ AISStream

**Архив:** `sea-radar-checkpoint--<short sha>.zip`, где short sha — короткий sha коммита, в который входит эта запись
**Дата:** 2026-09-21  **Задачи:** B-08…B-10

## Запуск

`npm install`
`npm run dev`

## Что сделано

- В репозитории создан `.env.example` с единственной строкой `AISSTREAM_API_KEY=` без значения.
- `.env.local` добавлен в `.gitignore`; `.env.example` оставлен разрешённым для Git.
- В `.claude/settings.json` добавлены deny-правила для чтения `.env`, `.env.local` и `.env.*.local`; `.env.example` этими правилами не запрещён.
- Создан серверный Route Handler `GET /api/snapshot` на Node runtime.
- При отсутствии ключа endpoint возвращает HTTP 502 с кодом `no_api_key` и фиксированным сообщением.
- При наличии ключа сервер открывает WebSocket к AISStream, отправляет подписку с районом, APIKey и фильтром `PositionReport`, пропускает `SubscriptionConfirmation` и возвращает первое фактическое сообщение как `raw`.
- Реализованы 15-секундный срок reader, результат `raw: null` для открытого соединения без сообщения, фиксированные коды ошибок и очистка таймера/обработчиков/соединения.
- API-ключ не включается в ответ и не выводится в диагностике.
