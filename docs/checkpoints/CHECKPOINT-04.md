# Checkpoint 04 — преобразование, сбор снимка и интерфейс настоящих позиций

**Архив:** `sea-radar-checkpoint--<short sha>.zip`, где short sha — короткий sha коммита, в который входит эта запись
**Дата:** 2026-09-21  **Задачи:** B-11…B-13

## Запуск

`npm install`
`npm run dev`

## Что сделано

- Добавлен преобразователь одного сообщения `PositionReport` из фактической структуры sample в существующую структуру `Vessel`.
- Добавлена валидация MMSI, координат, времени, скорости и курса по правилам SPRINT-02; невалидная позиция не создаёт судно.
- Формат `MetaData.time_utc` с наносекундами и `+0000 UTC` преобразуется в ISO 8601 с миллисекундами.
- Reader развёрнут в сборщик: за одно обращение собираются валидные суда, до 100 уникальных id, с дедупликацией по timestamp.
- Новое сообщение с более новым временем заменяет весь объект судна; при равных метках сохраняется первое принятое сообщение.
- Успешный ответ `/api/snapshot` содержит `vessels`, `collectedAt`, `windowSeconds`, `count`, `truncated` и `reason`.
- При ошибке частичный набор не возвращается; общий lifecycle завершает результат один раз и очищает таймер, обработчики и WebSocket.
- В существующий компонент карты добавлена кнопка «Загрузить настоящие позиции» и состояния `idle-demo`, `loading`, `success`, `empty`, `error`.
- В idle-demo сохраняются три учебных судна и их движение; при загрузке demo-таймер останавливается, текущие суда и выбор очищаются.
- Настоящие суда отображаются существующими значками и выбираются существующей карточкой; второй компонент карты и вторая карточка не добавлялись.
- Добавлены sample и provenance фактически полученного `PositionReport`, использованные преобразователем.
